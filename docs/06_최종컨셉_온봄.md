# 최종 컨셉 (대상권 전략): 온봄 (ON:BOM)

> **안산 폭염·한파 취약골목 AI 관제 에이전트** — 기후재난의 '마지막 1km' 관제탑
>
> 한 문장: **"기상청이 '내일 안산 35℃'를 말할 때, 온봄은 '내일 14시 원곡동 ○○길 — 야외작업 외국인 근로자와 독거노인이 겹치는 위험 골목 TOP5, 비어있는 그늘막·쉼터, 지금 내보낼 다국어 안내문'까지 말한다."**
>
> ※ 온봄 = 溫(온도) + 봄(살펴봄). 여름엔 폭염, 겨울엔 한파 — 같은 엔진이 사계절 돈다.

## 0. 왜 피벗인가 — 다봄케어 v2(86점)의 한계 정직 진단

| 축 | 다봄케어 v2 | 온봄 |
|---|---|---|
| AI 활용 (동점자 2순위) | 16/20 — 집계데이터 스코어링. **2026년 공모전 제목에 'AI'가 신설된 해에 가장 얇은 축** | 실측 라벨(온열질환 사례) 기반 예측 ML + LLM 다국어 생성 + 채널 집행 에이전트 = 3단 AI |

| 정치 리스크 | 외국인 예산 프레임 잔존 | 없음 (재난 대응 = 만인 공감; 외국인은 '취약계층 중 하나'로 자연 포함) |

다봄케어의 강점(외국인 데이터·다국어 자산·포용 AI 국가 스토리)은 온봄의 **취약계층 모듈로 100% 흡수**된다 (§5, §9).

## 1. 문제 정의 — "마지막 1km 공백"

- 국가는 위를 채웠다: 기상청 2026년 **폭염 중대경보·열대야주의보 신설**, 제4차 국가 기후위기 적응대책에 "AI 재난 예경보 + 취약계층 맞춤 지원" 명시. 그러나 예경보의 단위는 **시·군 전체**다.
- 현장은 골목 단위로 다르다: 같은 35℃에도 그늘 없는 산단 야외작업장, 노후주택 밀집 골목, 언어장벽으로 재난문자를 못 읽는 외국인 주민(안산 10.1만, 13.3%)의 위험은 다르다. 2025년 전국 온열질환자 4,431명, 최다 발생장소는 **작업장** — 안산은 공장 440개·반월산단 입주기업의 도시다.
- 행정의 실집행 질문에 답하는 도구가 없다: "**오늘, 어느 골목에, 무엇을(그늘막·순찰·안내문·쉼터 연장), 어떤 언어로** 내보낼 것인가" — 국토부 선행분석(15147787)은 연 1회 정적 지도에서 멈췄고, 무더위쉼터 입지 연구는 논문에서 멈췄다. **감지→예측→집행을 닫는 도구는 전국 어디에도 없다.**

## 2. 서비스 구조 — 3-루프 관제 에이전트 (행정 도구)

**정체성: 스마트도시과·재난부서·보건소가 함께 쓰는 폭염 관제탑** (2025 최우수 '도로위험 분석 관리자 페이지'와 동형의 행정 도구 + 2026년형 AI 심장)

```
[루프1 위험 예측]                [루프2 자원 매칭]                [루프3 집행·학습]
 기상 실황·예보(시간대) ×         위험 골목 TOP-N ×                VMS 전광판·재난문자 초안·
 골목별 취약인구(시간대 유동·      쉼터/그늘막/개방화장실/          시 다국어 챗봇·지원본부 채널로
 내외국인·연령·작업장) ×          공원/와이파이 거점 커버리지  →    다국어 안내 자동 생성·송출 제안
 온열질환 실측 사례 학습     →    공백(sheltering gap) 산출         + 실제 발생·이용 데이터 재학습
```

- **루프1 (AI 예측)**: 질병청 온열질환 사례(어느 날·어떤 조건에서 발생했나 = 라벨) × 기상청 시간대 기온·습도 × 행정동별 인구구조(내외국인·고령) × 시간대별 유동인구(내외국인 구분) × 산단 입주기업 종업원수(작업장 노출 프록시) → **"골목×시간대 폭염 위험 스코어"** (그래디언트 부스팅 + SHAP 설명)
- **루프2 (최적화)**: 위험 스코어 지도 위에 그늘막쉼터·무더위쉼터·개방화장실·도시공원·경로당(이재민수용시설 데이터) 커버리지를 중첩 → **보호 공백 골목** 도출 + 이동식 그늘막/살수차/순찰 동선 최적 배치 + 내년 예산(신규 쉼터 입지) 근거 자동 산출
- **루프3 (생성·집행)**: 공백 골목별로 LLM이 **상황 맞춤 다국어 안내문**(한/영/중/베/러 등 — 세계맛집 데이터의 다국어 자산, 국적별 인구 구성 반영) 초안 생성 → 시 보유 채널(VMS 도로전광판, 재난문자, 실증 중인 26개 언어 챗봇, 외국인주민지원본부 SNS)로 송출 제안 → 익일 실측(온열질환 신고·쉼터 이용)으로 모델 재학습. **겨울엔 데이터소스만 한파·한랭질환으로 바꿔 그대로 운전.**

## 5. AI 스택 (심사 ②축 — 3단 구성)

1. **예측**: XGBoost/LSTM — 입력(기상×인구×작업장×인프라) → 출력(골목×시간대 위험 스코어). **질병청 실측 사례로 학습·백테스트** (2023~2025 여름 재현 검증 → "작년 안산 온열질환 발생일 중 ○○%를 사전 고위험일로 적중" 형태의 성능 제시)
2. **생성**: LLM+RAG — 위험 골목의 국적 구성(행정동 외국인 데이터)에 맞춘 다국어 안내문·행동요령 자동 생성, 저건강문해력 버전 병행. AI 기본법(2026.1 시행) 생성물 표시 의무 선제 준수
3. **에이전트**: 감지(기상 API 트리거)→예측→매칭→초안 생성→담당자 승인(human-in-the-loop)→채널 송출→익일 실측 재학습의 자동 루프. 판단 근거는 SHAP으로 설명 (책임 AI)

## 6. 효과성 정량화 (실측 baseline 보유)

- **Baseline**: 질병청 감시 데이터에서 안산시 온열질환 신고 건수·발생장소 분포 직접 산출 (전국 2024년 3,704명 / 2025년 4,431명, 최다 발생장소 = 작업장)
- **1차 효과**: 고위험 골목·시간대 선제 개입(그늘막·순찰·다국어 안내)으로 온열질환 신고 감축 목표 — 온열질환 1건당 응급의료·손실 비용과 사망 예방 가치로 환산 제시
- **행정 효율**: 시 전역 균등 순찰 → 위험 상위 골목 집중으로 동일 예산 대비 커버리지 상승; 신규 그늘막·쉼터 입지의 데이터 근거화 (예산심의 방어 논리 제공)
- **형평 효과**: 재난문자를 읽지 못하던 10.1만 외국인 주민에게 모국어 도달 — "AI 기본사회(모두를 위한 AI)" 국정기조 정합
- **전 시민 체감**: 폭염은 특정 계층이 아닌 전 시민 문제 (다봄케어 대비 수혜 폭 확대)

## 8. 심사 라운드별 각본

- **1차 서류 (~7/17)**: 기획서 절 구성을 심사항목 순서 그대로(공공데이터 활용→AI→기획→효과→창의). 데이터 출처표(§4) 원형 첨부. 첫 페이지에 한 문장 컨셉 + 위험지도 목업 1장
- **2차 발표 (7/30, 상록구청)**: 오프닝 — "**오늘 안산 최고기온 ○○℃. 온봄이 지목한 오늘의 위험 골목 5곳입니다.**" (심사 당일 실데이터 라이브) → 3루프 데모(실데이터 위험지도 + LLM 다국어 안내문 생성 시연) → 질병청 백테스트 성능 → 겨울 한파 모드 전환 → 전국 확장. 15분 중 데모 5분
- **동점자 규칙**: ①공공데이터(15+ 실존 결합) ②AI(3단 스택) — 두 축 모두 구조적 우위 설계
