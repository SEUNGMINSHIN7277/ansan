# 모두의 사이렌 — 국가재난문자 AX(AI Transformation) 확장 설계

> 확장 지시: 도달률을 넘어 **국가재난문자의 전반적 pain point를 리서치로 검증하고, 감지→검증→전달 전 과정의 AX로 구체화**
>
> 컨셉 재정의(한 문장): **"재난문자의 전 생애주기 — 감지·검증·작성·표적·전파·도달 — 를 AI로 전환해, '발송했다'가 아니라 '몇 분 만에, 몇 %에게 닿았다'로 말하게 만드는 대한민국 최초의 재난 커뮤니케이션 AX. 안산에서 실증하고 전국의 표준이 된다."**

---

## 1. 리서치로 검증한 국가재난문자의 Pain Point 지도

| 단계 | Pain Point | 검증된 실제 사례·근거 (출처) |
|---|---|---|
| ① 감지 | 위험 신호는 도시에 이미 있었지만, 발송 담당자에게 종합되지 않는다 | 오송 참사(2023.7.15): 참사 1시간 전 119 신고 존재, 홍수경보 발령 중이었으나 지하차도 경고문자는 **사고 2시간 29분 후(11:49)** 발송. 사고 5분 전 문자는 '저지대 침수 위험' 일반 문구로 지하차도 미언급 (충북인뉴스·위키백과·국무조정실 브리핑) |
| ② 검증 | '확신이 없어서 늦게'와 '검증 없이 잘못'의 양극단 | 이태원(2022.10.29): 첫 신고 22:15 → 첫 재난문자 **23:55, 1시간 40분 후**. 재난문자 발송 요청이 **78분간 묵살** (머니투데이·뉴스타파 타임라인) / 서울 경계경보 오발령(2023.5.31): 사이렌 급 문자에 '왜·어디로'가 없었고 **22분 후 행안부 '오발령' 정정** (경향신문) |
| ③ 작성 | 담당자가 빈 화면에서 수동 작성 — 시간 소요 + 품질 편차. "안전에 유의하시기 바랍니다"식 무행동 문구 | 서울 오발령 문자: 대피 사유·장소 부재로 혼란 가중 (경향신문). 90자 제한이 2026년 하반기 **157자로 전국 확대**되지만, 커진 그릇을 '무엇으로 어떻게' 채울지는 여전히 담당자 재량 (뉴스핌 2026.6.29 「하반기 달라지는 것」·정책브리핑) |
| ④ 표적 | 시군구 전체 살포 → 무관한 수신 → 피로 → **알림 차단 → 정작 위험할 때 못 봄** ('양치기 소년' 악순환) | "'스팸' 취급받는 재난문자… 피로감에 알람 끄는 시민들" (한국일보 2023.7). 행안부도 중복 발송 방지 기능 도입으로 문제 인정 (정책브리핑) |
| ⑤ 전파 | CBS(휴대폰) 단일 채널 의존 — 알림 끈 사람·폰이 없거나 못 보는 상황(운전·작업·수면)·한국어 비문해자에게 공백 | Emergency Ready App은 영·중·베·태·일 5개 언어 '풀형 앱' — 설치자에게만 도달, **러시아어 미지원** → 안산 고려인 약 2.3만 명 제도적 사각 (App Store·정책브리핑·땟골 인구는 위키백과·남도일보) |
| ⑥ 도달확인 | **국가는 '발송 건수'만 알고 '도달'을 모른다** — 성과지표 부재로 ①~⑤가 개선 루프를 못 탄다 | 도달률을 측정하는 서비스·지표·사업이 검증 범위 내 무선례 (07 문서 선행 전수조사) |

**요약**: 행안부의 2026년 개편(157자·중복 방지)은 '그릇'과 '중복'만 다룬다. **감지의 속도, 검증의 확신, 문안의 품질, 표적의 정밀도, 채널의 다중화, 도달의 측정 — 6개 공백이 AI의 자리다.**

## 2. 북극성 지표 2개 (효과성의 언어)

| 지표 | 정의 | 현재 (검증 사례) | 목표 |
|---|---|---|---|
| **TTR** (Time-to-Reach) | 위험 신호 최초 포착 → 위험 노출 인구 도달까지의 시간 | 오송 2시간 29분+, 이태원 1시간 40분 | **5분 이내** (신호→검토 트리거 1분 + 검증·승인 3분 + 다채널 송출 1분) |
| **Reach Rate** (도달률) | 위험 노출 인구 중 '읽고 행동할 수 있는 형태'로 정보를 받은 비율 | 측정 자체가 부재. 언어 기준 안산 상한 ~85% (외국인 15.2%) | **95%+** (다국어·다채널·상점 노드) |

→ "재난 커뮤니케이션에 성능 지표를 부여한 최초의 시스템" — 이 두 숫자가 기획서·발표·확장 서사의 척추다.

## 3. 6단계 AX 파이프라인 (안산 실증 설계 — 전 데이터 검증 완료)

### ① 감지 (Detect) — "도시가 스스로 이상을 느낀다"
- **AI**: 시가 이미 보유·개방한 실시간 신호를 상시 감시하는 이상탐지(anomaly detection) → "재난문자 발송 검토" 트리거를 담당자에게 자동 발제
- **안산 데이터(전량 실존 검증)**: 도로 교차로 CCTV — 메타데이터에 '재난감시용' 명시 (data.go.kr/data/15144725) / 운영구간 교통흐름·속도 통합정보 — 특정 구간 속도 급락·통행 급감 = 침수·사고 프록시 (15149365) / 기상청 단기예보·특보 API / 한강홍수통제소 표준수문DB 실시간 수위·강수 Open API (data.go.kr/data/3040409) / 국가하천 하천범람지도 API (15141722) + 안산시 하천 28개 지정현황 (15036751) / 일별 강우량 10년 (15111852 — 임계값 학습용 과거자료)
- **오송 반사실**: 수위 API 임계 초과 + 지하차도 구간 교통 이상 → 발송 검토 트리거가 **사고 1시간 전** 담당자 화면에 뜬다

### ② 검증 (Verify) — "확신을 3분 안에"
- **AI**: 트리거에 대해 다중 신호 교차검증(수위+기상+교통+CCTV 화면 호출)으로 **신뢰도 스코어 + 근거 묶음**을 생성해 담당자에게 제시. 발송·보류·반려는 **사람이 결정** (human-in-the-loop — 오발령 책임 구조를 시스템으로 보호)
- **효과**: '확신 부족 → 78분 묵살'(이태원)과 '검증 없는 오발령'(서울)의 양극단을 동시에 제거. AI 기본법(2026.1 시행)의 설명가능성 요구를 근거 묶음 UI로 선제 충족

### ③ 작성 (Compose) — "157자를 3초 안에, 사람이 승인"
- **AI**: LLM이 재난 유형·위치·검증 근거를 입력받아 **157자 표준 골격(무엇이/어디서/누구는/어떻게) + 가장 가까운 대피시설**을 자동 작성 — 이재민수용시설 100여 개소 좌표 (15036519) 연결. 동시에 쉬운 한국어·다국어 20종(러시아어·우즈베크어 포함) ·음성(TTS) 버전 생성
- **2026년 타이밍**: 행안부가 157자로 그릇을 키운 바로 그 해, "그릇을 채우는 AI"로 등장 — 정면충돌이 아닌 **공식 개편의 다음 단계** 포지셔닝

### ④ 표적 (Target) — "필요한 사람에게만, 그래서 신뢰를 지킨다"
- **AI**: 위험 반경·유형별로 노출 인구를 계산해 발송 범위를 읍면동/골목 단위로 제안 — 행정동별 내외국인 인구 (3069669) × 시간대·내외국인 유동인구 (15135458 + 경기데이터드림 안산 전용 Open API) × 국적 구성 (행안부 외국인주민현황 승인통계·경기도 DT_210J0002)
- **효과**: 무관 수신 최소화 → 피로도·차단율 하락 → '진짜 경보'의 신뢰 회복 (양치기 소년 루프 차단)

### ⑤ 전파 (Deliver) — "CBS가 못 닿는 곳을 도시가 민다"
- **AI 오케스트레이션**: CBS 발송과 동시에 VMS 도로전광판 (15144791·15144790) / 버스정류소 안내 (경기데이터드림 정류소 API) / **'동네 사이렌' 상점 노드** — 세계맛집 4개 언어 (15152605)·안산상품권 가맹점 위경도 (15138163) 기반 외국인 밀집 상점의 사장님 폰·매장 화면 / 시 26개 언어 챗봇(실증 중)·외국인주민지원본부 채널 / 공공와이파이 거점 (15123133) 에 언어·채널별 변형 메시지를 동시 송출
- **취약도 가중**: 노인·독거노인 행정동 데이터 (3070454), 외국인 건강검진·적용인구 (15118612·15129529) 로 우선 채널 증설 골목 결정 (다봄 모듈) / 폭염·한파 시즌엔 그늘막·무더위쉼터 레이어 (15129447·15013199) 결합 (온봄 모듈)

### ⑥ 도달확인·학습 (Confirm & Learn) — "측정이 개선을 만든다"
- **AI**: 발령 직후 도달률(언어·채널·골목별)과 TTR을 자동 산출 — 긴급재난문자 API (15134001)·지역별 발령이력 (15091495)·지역코드 (15066113) × 인구·유동 데이터의 결정론적 계산. 사후 리뷰 리포트(어느 골목·어느 언어가 공백이었나)를 자동 생성 → ④·⑤의 파라미터 갱신
- **거버넌스**: 모든 단계 로그를 남겨 감사 가능 (재난문자방송 기준·운영규정 준수, 시 안전총괄·통합관제 승인 워크플로)

## 4. 왜 안산이 이것을 할 수 있고, 해야 하는가

1. **권한**: 재난문자의 상당수는 시군구가 직접 작성·승인·발송한다 — 이 AX는 남의 시스템 비판이 아니라 **안산시 자기 업무의 혁신** (스마트도시과·안전총괄 실무 도구)
2. **데이터**: 감지(CCTV·교통흐름·수문)~도달(인구·유동·국적·상점·VMS)까지 **전 단계를 개방 데이터로 조립할 수 있는 드문 도시** (본 문서 §3의 전 항목이 세션 내 실존 검증 완료 — 조건부 점검 불필요)
3. **필요**: 외국인 15.2% 전국 최상위(행안부 승인통계, 경기 1위)·고려인 러시아어권 2.3만의 도달 사각 — 도달률 문제의 최대 피해 도시이자 최적 실증 도시
4. **서사**: 세월호의 도시 — "전달되지 않은 경고, 작동하지 않은 안내방송"의 무게를 국민 누구나 안산과 연결해 기억한다. 안산이 '전달되는 경고'의 표준을 만든다는 것은 그 자체로 국가적 상징

## 5. 효과성 — 반사실(counterfactual) 시나리오 (발표 데모 설계)

**데모: "그날의 타임라인을 다시 돌린다"** (실데이터 리플레이)
| 시각 | 실제 (오송, 2023.7.15) | 모두의 사이렌 적용 시 |
|---|---|---|
| T-60분 | 홍수경보·119 신고 — 담당자에게 종합 안 됨 | ① 수위 API 임계 초과 + 교통 이상 → 발송 검토 트리거 |
| T-57분 | — | ② 교차검증 근거 묶음 → 담당자 승인 |
| T-55분 | — | ③ 157자 문안+대피 경로 자동 작성 ④ 지하차도 통과 예상 인구 표적 |
| T-54분 | — | ⑤ CBS+VMS+정류소+상점 노드 동시 송출 ⑥ 도달률 91% 확인, 미도달 골목 재송출 |
| T+0 | 침수 발생 (사망 14명) | **회피 가능 시간 54분 확보** |
| T+149분 | 지하차도 경고 문자 발송 | — |

- 안산 적용 수치: 시민 7명 중 1명(언어 사각) 도달 회복 = 약 10.2만 명, TTR 2시간29분→5분
- 행정 효과: 담당자 문안 작성·검토 부담 축소(157자 시대 필수 도구화), 오발령·중복 발송 리스크 구조적 감소, 전 발령의 도달률 KPI 자동 리포트

## 7. 기획서 목차 초안 (심사항목 정렬)
